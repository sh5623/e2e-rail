# e2e-rail v0.1.0 — implementation rulings

Decisions the controller made while executing the plan (subagent-driven development, 2026-10-07). Each line: what was decided — why — what it costs if wrong. Where a ruling and the design spec differ, the ruling describes the shipped behaviour.

- Ruling R0: commit locally per task on branch feat/v0.1.0, never push, never tag-push, never touch other repos — the user approved a plan whose every task ends in a commit and asked to build in this repo, while their global rule forbids unrequested commits; local branch commits are the reversible middle — cost if wrong: user resets/squashes the branch.
- Ruling R1: execute T5 (fixture) right after T1, then T2, T3, T4 — removes the plan's "temporary fixture then overwrite" step — cost if wrong: none.
- Ruling R4: test-list and shard lines are relative to Playwright `rootDir` (from `--list --reporter=json` → `config.rootDir`), stored in the spec index (`rootDir`, app-relative) and in every ledger entry; `listTests` returns `{ rootDir, tests }` — verified in playwright@1.61.0 lib/runner/index.js loadTestList and lib/common config `rootDir: resolve(configDir, testDir) || configDir` — cost if wrong: selected runs execute zero tests (contract test T17 guards).
- Ruling R5: run sets `PLAYWRIGHT_JSON_OUTPUT_FILE` (and `PLAYWRIGHT_JSON_OUTPUT_NAME` for older Playwright); stub reads FILE ?? NAME — cost if wrong: missing JSON report → empty ledger rows.
- Ruling R6: every abs→app-relative conversion goes through `realpathSync` on both sides; test helper returns realpath of the temp dir — cost if wrong: mis-relative paths on symlinked dirs.
- Ruling R7: changed-file git helpers use `--relative` so paths are relative to config.root — cost if wrong: misclassification when config is not at the git toplevel.
- Ruling R8: spec-index resolves spec/support imports with `ts.resolveModuleName` + app tsconfig (same as graph), no `@/` hardcode — cost if wrong: some aliases unresolved → spec imports missed (widening still covers src via graph).
- Ruling R9: default `run.modeEnv = { dev: {}, preview: {} }`; fixture config sets `modeEnv: { preview: { E2E_PREVIEW: '1' } }` (T3 assertion keeps holding) — spec §9 wins — cost if wrong: repos must declare their preview env explicitly (documented in template).
- Ruling R10: in T9 tests, `scripts/x.mjs` with app root `.` asserts `app-other`; unknown-root is tested with a 2-app `withDefaults(..., { checkFiles: false })` config — cost if wrong: none.
- Ruling R11: one `codeIdOf(config)` (select.mjs) used by fingerprint; untracked hashing excludes `${config.ledger.dir}/`; sample-app fixture ships `.gitignore` = `.e2e-rail/ dist/ test-results/ playwright-report/ blob-report/ argv.json` (never node_modules) — cost if wrong: verify always stale.
- Ruling R12: `newId` lives in `src/util/id.mjs` (crypto random 4 hex) — cost if wrong: none.
- Ruling R13: `select({ config, ts?, ... })` loads TypeScript per app when `ts` is absent — cost if wrong: none.
- Ruling R14: `runTests` strips `--e2e-rail-*` args from the spawn argv but keeps them in `command`; measureWorkers passes `['--e2e-rail-purpose=measure']` only — cost if wrong: none.
- Ruling R15: run `kind` is derived from inputs (`lastFailed`→rerun, `shard`→shard, `testList`→selected, else full); a caller `kind` never overrides — cost if wrong: none (stricter).
- Ruling R16: shadow pairing uses current `selection.json` when its codeId matches the run; else newest file in `selections/` by mtime with matching codeId — cost if wrong: pairs with an older selection of the same code.
- Ruling R17: CLI declares `no-lock`, `no-build`, `no-uncommitted` as explicit boolean options; CLI tests run with `CI` removed from env — cost if wrong: none.
- Ruling R18: Codex `plugins/e2e-rail/hooks/hooks.json` command = `cat "$PLUGIN_ROOT/hooks/doctrine.md"` (verified in sh5623/self-improvement Codex package) — cost if wrong: Codex doctrine not injected.
- Ruling R19: contract test symlinks the repo's `node_modules` into the temp app so the real `@playwright/test` resolves — cost if wrong: contract test can't run locally.
- Ruling R20: T17 stops after contract test + CHANGELOG + sync; tag/push, guardrail listing and bfm-fo-front adoption are left to the user (outward-facing; bfm working tree is dirty with unrelated work) — cost if wrong: user runs those steps.
- Ruling R21: `"test": "node --test test/*.test.mjs"`, `"test:contract": "E2E_RAIL_CONTRACT=1 node --test test/contract/*.test.mjs"` — cost if wrong: none.
- Ruling R22: for a commit-metadata-only finding (trailer), the controller verifies the amended message with git log instead of a re-review subagent — review-package cannot diff an amended (non-descendant) commit and there is no code delta to review — cost if wrong: none.
- Ruling R23: Task 9's dispatch also patches src/util/git.mjs (`--no-renames` on gitUncommittedFiles' diff) and src/util/hash.mjs (hashFiles skips directory entries and hashes symlink targets as link text via lstat; missing paths are skipped) with tests — both feed codeIdOf/selection, which Task 9 introduces — cost if wrong: one extra file touched by Task 9.
- Ruling R24: accept Task 6 widening deviations (any unresolved spec goto → unmapped even if other routes resolve; unresolved non-final template segment → prefix + `**`, routeMatches understands spec-side `**`; shadowed identifiers not resolved) and accept skipping unresolvable `page.route(fn)` predicates (bfm: 658 predicate routes would put `**` on 142/145 specs and erase the API axis; the graph axis remains the union partner) — cost if wrong: API axis covers fewer specs in repos using predicate routes.
- Ruling R25: support-module `goto` calls whose argument resolves to a literal ARE merged into the importing spec's routes (union, same rule as apis); unresolvable support gotos (parameterised helpers) are ignored and do not mark the spec unmapped — spec §0 "좁혀서 틀리지 않는다": a resolvable route the spec visits through a helper must not be dropped — cost if wrong: mild over-selection (e.g. a login helper's goto('/app/') adds route '' to its users).
- Ruling R26: with R25, `unmapped` is decided by the spec's OWN resolved routes (`ownRoutes.size === 0 || unresolvedOwn`); support-merged routes never make a spec mapped — otherwise a spec navigating only via helpers that imports a support module containing one literal goto would flip from unmapped to a single wrong route — cost if wrong: none (strictly wider).
- Ruling R27: test files that Playwright lists but that lie outside `specDir` enter the index as `{ routes: [], apis: [], imports: [], supports: [], projects, unmapped: true }` — spec §0 widen-on-unknown — cost if wrong: those specs run on every src change.
- Ruling R28: graph BFS treats route-table files as boundaries — from an adapter entry file, importers that are route files (expandGlob of app.adapter.routeFiles) are NOT expanded; every other importer is. Any changed file whose BFS reaches main is a SHELL change → that app runs full (reason `graph-shell:<file>`), even if it also reached entries. Result shape `{ entries, unresolved, shell }` (replaces `mainOnly`); `affectedEntries(graph, changedRel, entryRel, mainRel, boundaryRel)`. Spec §5 rule "mainOnly only when no entry is hit" let a component shared by a layout (rendered on every route) and one page select only that page's specs — a narrowing hole found in Task 7 — cost if wrong: shared components imported by the shell widen to full more often.
- Ruling R29: accept Task 7 extensions — static `Component:` leaf routes map to the module they name; extra file src/adapters/pattern.mjs; `routeEntries` stays synchronous (spec text says Promise; callers in the plan are sync) — cost if wrong: none.
- Ruling R30: bfm adoption config must use `src/features/**/routes.tsx` (+ `src/routes/router.tsx`) — measured 188 entries / 0 unresolved vs 9 unresolved with `*` — goes into Task 16 README example — cost if wrong: none.
- Ruling R31: layout modules map to `${full}/*` (root `*`); brief test 1 expectation changes to `*` — a layout renders under every child route — cost if wrong: layout edits select every child spec (intended).
- Ruling R32: static entries only from leaf `Component: Ident` / self-closing `element: <Ident/>`; modules seen at any non-leaf position are never entries — cost if wrong: some static leaf pages fall back to shell → full.
- Ruling R33: route arrays may contain only object literals or spreads of verified local/covered array declarations; everything else (re-export to uncovered file, call result, parameter, helper-call arguments) → unresolved — cost if wrong: more full runs on unusual route tables.
- Ruling R34: compose route paths as absolute, normalise once — cost if wrong: none.
- Ruling R35: accept the implementer's R33 extension — a const array made only of identifiers/spreads in a route file counts as a route list (closes probe C and pdm-style aggregators; non-route arrays of imported identifiers become unresolved = safe) — and accept that `Component: () => <X …/>` arrow leaves are not entries (X then reaches main via the route file → shell → full; bfm 4 psm routes) — cost if wrong: 4 bfm routes run full instead of partial.
- Ruling R36: app.main override; mainRel null → all in-graph changes are shell (full) — cost if wrong: repos without a detectable main never narrow until they set app.main.
- Ruling R37: internal resolution failures recorded as graph.missing (assets and bare/virtual specifiers excluded); any missing → all changed files unresolved; readCompilerOptions errors on solution-style tsconfig without paths — cost if wrong: repos with a broken internal import never narrow until fixed (reported by map --check later).
- Ruling R38: literal glob/template/require.context/new URL patterns become edges; non-literal → importer opaque with edges to every src file — cost if wrong: repos with fully dynamic imports select more.
- Ruling R39 (corrects R7): changed-file helpers return paths relative to the git toplevel (no `--relative`); the selector converts them to config-root-relative, and any path outside config.root becomes `unknown-root:<path>` → every app full. Untracked files likewise. — R7 traded a misclassification for a silent drop; widening is the invariant — cost if wrong: repos whose config sits below the git root run full on any outside change (intended).
- Ruling R40: accept Task 10 deviations — maxMtime counts files by default (brief's own test failed); distStale counts dir mtimes so deletions mark dist stale (DEFAULT_SKIP exported); ledgerRel(config) replaces the literal '<ledger.dir>/' prefix (literal form fails for './x' or 'x/'); unknown mode throws; NUL separator in config hash — cost if wrong: none.
- Ruling R41: distStale compares the dist's newest file mtime with the newest mtime over every file git knows in the repo (tracked via `git ls-files -z` from the toplevel, plus non-ignored untracked), excluding the dist directory itself and the ledger dir; missing tracked files (deleted) count via their parent dir mtime — spec §0: any input the build may read can make dist stale; over-rebuilding is the safe error — cost if wrong: an unrelated tracked-file edit (docs) triggers a rebuild before preview runs.
- Ruling R42: runTests defaults `workers` to `process.env.CI ? app.run.workers.ci : app.run.workers.local` when the caller passes none (undefined → Playwright default), and runs the preview build command through a shell (`spawn(cmd, { shell: true, cwd: config.root })`) because build commands like `pnpm -F bfm build` are command lines, not argv — cost if wrong: none.
- Ruling R43: lock scope is machine-wide (spec §0 "heavy runs: one per machine"; §9's repo-hash wording loses to it): `lockDir()` = `$E2E_RAIL_LOCK_DIR` or `os.tmpdir()/e2e-rail-lock/machine`; this supersedes both the brief's config.root key and the implementer's git-common-dir key — overlapping heavy runs from different repos/worktrees contend for the same CPU and the same fixed E2E ports — cost if wrong: two unrelated repos' heavy runs serialise on one machine.
- Ruling R44: accept Task 12 deviations 2 (lock → build → fingerprint → spawn), 3 (no `--shard` when a test list is given), 5 (light-slot-then-check-heavy, atomic owner file, 10 s grace, owner-checked release/reap, pid-reuse/reboot orphan detection, signal forwarding, execInherit shell/onSpawn, 128+n). For deviation 4: every ledger entry carries `filtered: true|false` — true when `project` is set or passthrough contains a test filter (`--grep`, `-g`, `--grep-invert`, `--project`, `--only-changed`, `--last-failed`, or a positional file/line argument); filtered runs never update last-green and Task 13's verify never counts them — cost if wrong: none.
- Ruling R45: (background security review) lock base dir is created 0o700, must be a non-symlink directory owned by the current uid and not group/world-writable, reap/release never follow symlinks; Linux default path includes the uid — prevents another local user on shared /tmp from blocking runs or redirecting deletions — cost if wrong: a misconfigured TMPDIR needs E2E_RAIL_LOCK_DIR.
- Ruling R46: `runTests` rejects (readable error, before taking the lock, no ledger line) any passthrough argument — in `--opt`, `--opt value` or `--opt=value` form — among `--test-list`, `--test-list-invert`, `--shard`, `--last-failed`, `--list`, `--only-changed`, `-c`, `--config`, `--reporter`, `--output`; those are either first-class runTests parameters or would desynchronise the report/fingerprint. Remaining filters (`--grep`, `-g`, `--grep-invert`, `--project`, positional file args) keep `filtered: true` — cost if wrong: users pass those options through the dedicated CLI flags instead of `--`.
- Ruling R47 (narrows my Task-10-carried ruling): in preview mode, `dist === null` blocks verification only when the app declares `run.preview` (dist missing = not built); an app without a preview block verifies in preview mode on fingerprint/app/mode alone — cost if wrong: none.
- Ruling R48: accept Task 13 extras — recordShadow refuses a failed full run with zero recorded failures (crash/global-setup would be a vacuous hit); verify returns extra `shards`/`have`/`expired` fields and throws on invalid require/maxAgeMin; shadow records add `fp`, status adds `recentMisses`; damaged state.json falls back to shadow with a warning; promote not gated on streak (human decision) — cost if wrong: none.
- Ruling R49: a shard set counts as a full verification only when its members share one plan: native Playwright sharding (`--full --shard i/n`, no test list) records `shard.plan = 'native'`; planned shards (`--test-list <plan file> --shard i/n`) record `shard.plan = <planId>` and `shard.planCodeId`; `completeShardSet` groups by (count, plan); verify accepts a planned set only when `planCodeId` equals the current codeId; `planShards` enumerates the CURRENT test list via `listTests` (ledger durations only weight it) so a plan covers every test of the code it was made for — the reviewer showed a native 1/2 + arbitrary list 2/2 mix verifies as full, and a plan built from an old run would miss new specs — cost if wrong: CI must re-plan after spec changes (cheap: listTests).
- Ruling R50: measureWorkers runs take the HEAVY lock (exclusive) — a worker-count comparison overlapping other runs measures contention, not workers; `runTests` gains `lockClass: 'heavy'|'light'|undefined` (undefined = derived from kind as today) — cost if wrong: measurement waits for other runs to finish.
- Ruling R51: accept Task 14 extras (includeSpecs must be listed by Playwright; count > spec files and empty lists refused; equal weights without timings; codeId computed before listTests; stale <n>.txt removed; durationsFrom/retried fields; completeShardSet codeId default; exports fullUnits/MEASURE_TAG/verifiedShardSet; mergeReports html open never + only fresh index.html) — cost if wrong: none.
- Ruling R52 (refines R49): `runTests` derives planned-shard identity itself — when `shard` is given and `testList` is `<dir>/<i>.txt` with a `<dir>/manifest.json`, it reads the manifest and requires: manifest.app === app.name, i is one of the manifest's shard indexes, `shard.index === i`, `shard.count === manifest.count`, and sha256 of the list file equals the manifest's recorded `sha256` for index i (planShards records it per shard). Mismatch → readable error before lock/ledger. On success the entry records `shard = { index, count, plan: planId, planCodeId: manifest.codeId }`. The `shardPlan` parameter is removed (no caller-trusted identity); a test list without a manifest + shard stays `adhoc:<path>` — cost if wrong: renaming/editing plan files breaks a CI job loudly instead of verifying wrongly.
- Ruling R53: accept Task 15 extras (init keeps only routeFiles globs that match; strict usage errors exit 2; bare --selection/--base; exactly one run mode; --test-list resolved from cwd; selection-for-different-code warning; "nothing verified yet"; per-command --help). Pre-review adjustments: (a) spec §8 — every ledger entry records `shadowed: true|false` (true when kind=selected and shadow state trust=shadow at run time; runTests reads it via readState); (b) `lock run` with a command that cannot be spawned prints `e2e-rail: cannot run <cmd>: <reason>` and exits 127 (execInherit exposes the spawn error) — cost if wrong: none.
- Ruling R54: accept Task 16 design choices — GH template builds dist once and shares it (touch), shard ledger lines appended in the merge job so complete=yes is reachable, downloads kept in $RUNNER_TEMP outside the work tree (fingerprint), actions/cache holds duration history not last-green, docs use `verify --mode <mode run>`, tokens quoted from the CLI as built (`trust shadow`, graph-unresolved), drift test before sync — cost if wrong: none.
- Ruling R55: the contract fixture's Playwright tests use no browser fixtures (`test('a', () => expect(1).toBe(1))`-style), so the real-Playwright contract (list paths/rootDir, --test-list format, JSON reporter fields, ledger, verify) runs without downloading browsers; the CI contract job may keep or drop the browser install step — cost if wrong: browser-specific reporter fields untested (none are used).
- Ruling R56 (load-bearing, for the final fix wave): real Playwright exits 0 after running ZERO tests when a `--test-list` matches nothing (wrong path base, renamed spec). `runTests` must treat "test list with ≥1 non-comment line but zero tests in the JSON report" as a failure: record `rc: 1` (never rc 0 for it), a failure `{ file: null, title: null, project: null, error: 'test list matched no tests' }`, print one line `e2e-rail: test list matched no tests — check paths are relative to Playwright rootDir`, and return 1 — a silent empty pass would satisfy `verify --require selected` and shadow pairing — cost if wrong: none (an empty list is already skipped by the CLI).
- Ruling R57: README line 19 "not tagged yet" (en/ko) stays until the user tags; the finishing message tells the user to update it in the tagging step.
- Ruling R58: the final fix wave covers every item in final-fix-findings.md in ONE dispatch (opus); KEEP-AS-LIMIT triage lines stay documented limits (README Limits); R57 unchanged — cost if wrong: one larger fix diff to re-review.
- Ruling R59: accept final-fix extras — non-zero Playwright rc kept (only rc 0 → 1 on empty/lost lines); per-line loss check skipped for intentionally narrowed runs (--project/--grep/--last-failed; still fail when nothing ran; never verify); unreadable list after run = failure; config.ignore also never hides specDir test files; init suggests --mode preview for e2e:run too — cost if wrong: none.
