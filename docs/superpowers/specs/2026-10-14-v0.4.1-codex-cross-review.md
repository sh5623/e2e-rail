# e2e-rail 0.4.1 Codex 재검증

검증일: 2026-10-14 KST · 검토: Codex

대상: `78180796c5bc38d752dcf3b83888a5ec68a2e5ae`. 로컬 HEAD·원격 main·annotated `v0.4.1` tag의 대상 커밋이 일치한다. 검토 시작 시 소스 작업 트리는 clean이었으며, 테스트는 별도 임시 clone에서 실행했다.

## 판정

**0.4.0에서 발견한 P1 환경별 잘못된 요청 합류는 해결됐다. 이번 변경 범위에서 추가 결함은 발견하지 못했다.** 기존 환경 재현을 수정 대상 코드에 다시 실행했고, 새 계약 테스트만 신뢰하지 않고 원래의 대조군 결과와 비교했다.

## 원래 재현의 비교 결과

같은 clean 코드에서 환경 값만 바꿔 별도 CLI 프로세스를 실행했다. 첫 healthy 요청이 락을 보유하는 동안 broken 요청을 대기시키고, 이후 broken 요청을 단독 실행해 비교했다. 실제 Playwright 러너를 사용했으며 브라우저 fixture와 외부 서버는 사용하지 않았다.

| 관측 | 0.4.0 | 0.4.1 |
| --- | --- | --- |
| healthy producer | rc 0 | rc 0 |
| broken follower | 실행 없이 rc 0 | **직접 실행하여 rc 1** |
| follower 합류 | true | **false** |
| broken 단독 대조군 | rc 1 | rc 1 |
| 실제 환경 테스트 호출 | healthy, broken 대조군 | healthy, broken follower, broken 대조군 |

0.4.1 실행 원장은 `fingerprint.clean: true`, `joinPolicy: 1`을 기록했고 healthy/broken의 `envDigest`는 서로 달랐다.

## 변경과 검증

- `src/run.mjs`가 상속 환경, 실제 `run.env`/mode 환경, Node 경로·버전을 HMAC 지문에 포함한다. 실행마다 달라지는 두 JSON report 경로는 실제 러너에서 덮어쓰므로 비교에서 제외한다.
- `JOIN_POLICY = 1`은 기존 `VERIFY_POLICY = 2`와 분리된다. 환경 지문·합류 정책이 없는 구형 원장은 새 합류 대상이 아니다.
- `src/lock.mjs`가 private lock 디렉터리에 32바이트 키를 0600으로 생성하고, 소유권·파일 종류·크기·권한을 확인한다. 유효한 키가 없으면 합류하지 않는다. 키 symlink·잘못된 크기·공개 권한 등에 대한 회귀 테스트를 확인했다.
- 같은 환경의 요청은 여전히 합류한다. 환경으로 계산한 설정값이 다른 경우, 환경 값의 원장 평문 노출 방지, 구형 원장 및 keyless 실행의 합류 거부를 테스트한다.

## 유지되는 한계

**환경 비교는 합류에 적용되며 기존 verify의 fingerprint에는 들어가지 않는다.** 이번 재현에서도 broken 환경의 verify는 이전 healthy full 결과를 반환했다.

```text
verified: full@run-20261014-000001-97b6 (just now)
```

이 줄은 broken 환경 통과의 증거가 아니다. 현재 환경을 구분하지 않는 기존 verify의 한계를 보여준다. 환경 변경 후에는 직접 재실행해야 하며, verify-first 방식으로 실행을 생략하는 자동화까지 환경 변경에 안전해졌다고 해석하면 안 된다. README에 이 한계가 추가됐음을 확인했다.

또한 0.4.0 실행기가 남아 있으면 그 실행기는 0.4.1 원장도 환경 비교 없이 읽을 수 있다. 같은 작업 트리에서 실행하는 CLI를 함께 갱신해야 한다는 CHANGELOG의 안내는 타당하다. 이번 검토에서는 Codex 설치 파일을 확인했으며 다른 모든 실행기의 업데이트 여부까지 확인하지는 않았다.

에픽 통합 큐·다른 HEAD의 증거 재사용은 여전히 범위 밖이다. 데스크톱 SessionStart 및 실제 브라우저 UI도 이번 재검증 대상이 아니다.
